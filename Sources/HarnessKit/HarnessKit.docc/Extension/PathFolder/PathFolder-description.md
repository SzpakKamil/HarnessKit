The label displayed in the navigation list row for this folder option.

## Overview

In HarnessKit, the `description` property provides the user-facing title for each navigable option within a ``HarnessKit/PathFolder``. This string is used by ``HarnessKit/HarnessView`` as the primary label for the `NavigationLink` that leads to the option's destination view.

Typically, this property returns a human-readable string that should ideally match the accessibility identifier of the destination view. Consistent naming between the navigation label and the view's internal identifiers improves the usability of the harness app and facilitates automated UI testing using the `navigate(app:)` methods from the `HarnessKitTesting` module.

### Symbol Details

| Name | Type | Description |
| :--- | :--- | :--- |
| `description` | `String` | The human-readable label shown in the navigation list. |

> Important: All members of the ``HarnessKit/PathFolder`` protocol are isolated to the `@MainActor`.

### Default Behavior

If not explicitly overridden in a conforming type, `description` defaults to an empty string (`""`). While the navigation row will still be generated by ``HarnessKit/HarnessView``, it will appear without a visible label. It is highly recommended to override this property to provide meaningful titles for your component previews.

## Example

The following example demonstrates a complete HarnessKit hierarchy, showing how to implement custom descriptions for various cases within a folder.

```swift
import SwiftUI
import HarnessKit

// 1. Define the Project (Root)
// The PathProject defines the top-level entry point and root name.
enum ComponentLibrary: PathProject {
    static let name = "Design System"
    static let folders: [any PathFolder.Type] = [ButtonFolder.self]
}

// 2. Define the Folder (Section)
// The PathFolder groups navigable cases and sub-folders.
enum ButtonFolder: Int, PathFolder {
    typealias ParentSection = ComponentLibrary
    static let name = "Buttons"
    
    case primary
    case secondary
    case destructive
    
    // 3. Implement 'description' for each Case
    // This value is displayed as the title in the navigation List.
    var description: String {
        switch self {
        case .primary:
            return "Primary Action"
        case .secondary:
            return "Secondary Ghost"
        case .destructive:
            return "Danger Zone"
        }
    }
    
    @ViewBuilder
    var view: some View {
        switch self {
        case .primary:
            Button("Primary") { }.buttonStyle(.borderedProminent)
        case .secondary:
            Button("Secondary") { }.buttonStyle(.bordered)
        case .destructive:
            Button("Delete") { }.foregroundColor(.red)
        }
    }
}

// 4. Render the Hierarchy
// Use HarnessView to display the navigation tree.
struct AppRoot: View {
    var body: some View {
        HarnessView<ComponentLibrary>()
    }
}
```
